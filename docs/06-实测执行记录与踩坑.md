## 二、踩坑与解法（关键）

### 坑 1：WSL 曾被安全策略禁用
- 现象：`wsl.exe` 报 `Permission denied` / Program Blacklist。
- 解法：用户在安全中心放行后恢复。**本会话已解决**。

### 坑 2：PowerShell 执行脚本被策略拦截 + 中文乱码
- 现象：`无法加载文件 ... 因为禁止运行脚本`；改用 Bypass 后中文字符串按 GBK 解析报错。
- 解法：
  1. `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force`
  2. 脚本内容改为**纯 ASCII**（避免 UTF-8 中文在 PS 5.1 下乱码）
  - 注意：从 Bash 调用 PowerShell 会被安全拦截，必须用 PowerShell 工具本身执行。

### 坑 3：PowerShell 数组 `-notmatch` 陷阱
- 现象：`adb devices` 明明有设备，`if ($devs -notmatch $DEVICE)` 却判为失败。
- 原因：多行输出是数组，`-notmatch` 只要有一行不匹配就返回非空数组 → 为真。
- 解法：`$devs = (& $adb devices 2>&1 | Out-String)` 先转字符串再匹配。

### 坑 4：新版 fastboot 无 `dump_image` / `fetch`
- 现象：`fastboot: usage: unknown command dump_image`；`fetch` 报 `Device does not support fetch command`。
- 原因：本机 bootloader（lk）不支持分区读取。
- 解法：分区镜像备份不可行 → 改用 `adb pull /sdcard/` 备份用户数据（已备份 37 文件 / 6.6MB 到 `D:\backup\ugglite\20261119_103808\sdcard\`）。
- 回滚方案：改用小米官方线刷包（Mi Flash）恢复，而非分区镜像。

### 坑 5：pip 安装 pmbootstrap 失败
- 现象：PyPI 上 pmbootstrap 所有版本被 yanked → `No matching distribution found`。
- 解法：从 GitLab 源码安装（见坑 6）。

### 坑 6：postmarketOS 已迁移 GitLab
- 现象：`gitlab.com/postmarketOS/pmbootstrap` 提示已迁移；官方地址 `gitlab.postmarketos.org` 重定向到 `gitlab.nura.eco`（慢）。
- 解法：
  - pmbootstrap：`git clone --depth 1 https://gitlab.postmarketos.org/postmarketOS/pmbootstrap.git ~/pmbootstrap`
  - 用 venv 安装（`pip install -e ~/pmbootstrap`）规避 PEP 668。
  - pmaports：官方站主分支是 **`main`**（不是 master），用 `git clone --depth 1 -b main ...` 克隆。
  - **切勿用 gitlab.com 的旧镜像**（其 master 是 2024-11 快照，无 msm89x7 设备包）。

### 坑 7：pmbootstrap 配置文件名
- 正确路径：`~/.config/pmbootstrap_v3.cfg`（不是 `pmbootstrap.cfg`）。
- 关键字段：`device = qcom-msm89x7`（**必须是 vendor-codename 完整格式**，只写 `msm89x7` 会 `IndexError: list index out of range`）。
- 通道：`kernel = edge`，对应 pmaports 的 `main` 分支。

### 坑 8：init 交互卡住
- 现象：`pmbootstrap init` 逐项提问，管道输入不够或超时。
- 解法：预写 v3 配置后，用 `printf '\n%.0s' {1..25} | pmbootstrap init` 连续回车应答所有默认值。
- 注意：必须用 `python3 -u`（无缓冲）并重定向到日志文件观察，否则看不到进度。

### 坑 9：install 卡在 getpass 密码输入
- 现象：`OSError: [Errno 5] Input/output error` / `termios.error` —— `install.py` 用 `getpass` 从 /dev/tty 读密码，管道无效。
- 解法：加 `--password <临时密码>` 参数非交互安装：
  ```
  pmbootstrap install --password <TEMP_PASSWORD> --add "openssh,networkmanager,avahi,docker,tmux,htop,nano,curl,wget"
  ```
  首次登录后立即改密码。

### 坑 10：sudo 超时导致 init 失败
- 现象：`sudo: timed out`，`Failed to shut down all chroots`（pmbootstrap 调用 `sudo losetup` 时等密码）。
- 解法：配置 sudo 免密：
  ```
  echo "administrator ALL=(ALL) NOPASSWD: ALL" | sudo tee /etc/sudoers.d/pmbootstrap-nopasswd
  sudo chmod 440 /etc/sudoers.d/pmbootstrap-nopasswd
  ```

### 坑 11：Git Bash 下 wsl.exe 变量展开
- 现象：`wsl.exe -d Ubuntu -- bash -lc '...$HOME...'` 中 `$HOME` 被外层 Git Bash 提前展开为空。
- 解法：WSL 命令中一律写**绝对路径**（`/home/administrator/...`），不用 shell 变量。

## 三、正确的构建流程（已验证配置）

```bash
# 1. 依赖
sudo apt install -y python3-pip python3-venv git kpartx adb fastboot

# 2. pmbootstrap 源码 + venv
git clone --depth 1 https://gitlab.postmarketos.org/postmarketOS/pmbootstrap.git ~/pmbootstrap
python3 -m venv --system-site-packages ~/pmb-venv && source ~/pmb-venv/bin/activate
pip install -e ~/pmbootstrap

# 3. sudo 免密
echo "administrator ALL=(ALL) NOPASSWD: ALL" | sudo tee /etc/sudoers.d/pmbootstrap-nopasswd
sudo chmod 440 /etc/sudoers.d/pmbootstrap-nopasswd

# 4. 写 ~/.config/pmbootstrap_v3.cfg（device=qcom-msm89x7, kernel=edge, ui=none, service_manager=openrc）

# 5. init（连续回车）
printf '\n%.0s' {1..25} | python3 -u ~/pmbootstrap/pmbootstrap.py init --shallow-initial-clone

# 6. install（非交互密码）
python3 -u ~/pmbootstrap/pmbootstrap.py install --password <TEMP_PASSWORD> \
  --add "openssh,networkmanager,avahi,docker,tmux,htop,nano,curl,wget"

# 7. 导出
python3 -u ~/pmbootstrap/pmbootstrap.py export
```

验证过的状态输出：
```
Channel: edge (pmaports: main)
Device:  qcom-msm89x7 (aarch64)
UI:      none
systemd: no (openrc selected in pmbootstrap init)
```

### 坑 12：大内核包下载中断（反复失败）
- 现象：`ERROR: linux-postmarketos-qcom-msm89x7: Connection aborted / unexpected end of file`
- 根因：`mirror.postmarketos.org` 301 跳转到 `mirror.nura.eco`，该镜像站传 45MB 内核包时直连极慢且中断；
  apk 缓存里残留 15MB 残包（`...d02eb925.apk`），一直用残包导致反复失败。
- 解法：经 Windows 代理用 curl 完整下载补全缓存：
  - 端口转发（代理只监听 127.0.0.1，WSL 不可达）：
    `netsh interface portproxy add v4tov4 listenport=7891 listenaddress=0.0.0.0 connectport=7890 connectaddress=127.0.0.1`
  - WSL 内经 `http://<网关IP>:7891` 代理，curl 下载完整 45MB 包到缓存（脚本 `fetch-kernel-proxy.sh`）
- 缓存文件属主是 root，需先 `sudo rm` 残包，下载到 /tmp 后 `sudo cp` 回填。

### 坑 13：Windows 无 NCM 驱动，USB 网络不通
- 现象：设备 USB gadget 是 CDC NCM（`VID_18D1&PID_D001`），Windows 问题代码 28（无驱动）；
  `172.16.42.1` ping 不通。
- 第三方 INF 被签名强制拒绝；系统 usbncm.inf 不匹配该 VID/PID。
- 结论：放弃 USB 网络，改走 Wi-Fi（无需 Windows 驱动）。

### 坑 14：Wi-Fi 配置写了但不自动连 —— NetworkManager 未在 default runlevel
- 现象：镜像里写了 `/etc/NetworkManager/system-connections/<YOUR_WIFI_SSID>.nmconnection`，但开机不连。
- 根因：`/etc/runlevels/default/` 里**没有 networkmanager 符号链接**，服务没启动。
- Wi-Fi 凭据来源：从 Windows 已保存配置导出（`netsh wlan show profile name="<YOUR_WIFI_SSID>" key=clear`）。
- 解法：离线挂载镜像根分区（kpartx 映射 loop0p2 → ext4），
  补符号链接 `ln -s /etc/init.d/networkmanager /etc/runlevels/default/networkmanager`（脚本 `fix-networkmanager.sh`），重刷。

### 镜像离线修改通用流程
```
sudo kpartx -av qcom-msm89x7.img        # 映射出 loop0p1(/boot) loop0p2(根)
sudo mount /dev/mapper/loop0p2 /tmp/mnt
# ... 修改文件 ...
sudo umount /tmp/mnt && sudo kpartx -d qcom-msm89x7.img
```

### 坑 15（致命）：SSID 手误写错（多了个尾字母）
- 现象：所有脚本/镜像里 Wi-Fi 名称比真实 SSID 多写了一个字母 X，设备反复连不上。
- 根因：从 Windows 导出配置时（`netsh wlan show profile name="<YOUR_WIFI_SSID>" key=clear`）复制 SSID 手误多了个字符，密码却一直是对的。
- 教训：Wi-Fi SSID 与密码务必让用户当面逐字符确认，不要凭记忆或导出结果直接写入；这类错误极难从"连不上"的表面现象反推。
- 已全量修正 `scripts/linux/*.sh` 与镜像内的 `.nmconnection` 配置。

### 坑 16：镜像缺 wpa_supplicant 与 wcnss 固件加载器
- 现象：SSID 改对后仍连不上。dmesg 显示 `wcn36xx` 网卡能起来但 wlan0 一直 DOWN。
- 根因1：构建未装 `wpa_supplicant`（NetworkManager 无 WPA 认证后端）。
- 根因2：`firmware-qcom-msm89x7` 包只带 motorola 机型 nv 文件；
  本机的 WCNSS Wi-Fi 固件需 `msm-firmware-loader-wcnss` 子包从 Android persist 分区提取。
- 解法：`pmbootstrap_v3.cfg` 的 extra_packages 加入
  `wpa_supplicant,wpa_supplicant-openrc,msm-firmware-loader-wcnss`，重建镜像。

### 坑 17：Windows 电脑无法做 Wi-Fi 热点
- 现象：`netsh wlan start hostednetwork` 报"状态不可用"。
- 根因：Realtek 8821CE 驱动 `支持的承载网络: 否`（SoftAP 不支持）。
- 结论：热点方案放弃。（Wi-Fi Direct 虚拟适配器虽在，但需设备先能连 Wi-Fi 才有意义。）

### 坑 18：USB RNDIS/NCM 驱动签名死结 → 改用 USB ACM 串口（关键突破）
- NCM/RNDIS gadget 在 Windows 均报代码 28；自定义 INF 无数字签名被拒
  （`pnputil /add-driver` 报"第三方 INF 不包含数字签名信息"）。
- 突破：把 USB gadget 改为 **CDC-ACM 串口**（configfs `functions/acm.0`），
  Windows 内置 `usbser.sys` 自动识别为 COM 口，无需签名。
- 设备侧在 `/etc/inittab` 加 `ttyGS0::respawn:/sbin/getty -L 115200 ttyGS0 vt100`。
- 结果：刷机后枚举为 <COM_PORT>，串口直接登录 `user/<TEMP_PASSWORD>`，拿到运行时 shell。
- 复用脚本：`D:\pmos-images\serial-shell.ps1`（串口登录执行命令）、`usb-gadget.sh`。

### 坑 19：NetworkManager 自动连 Wi-Fi 不可靠 → 最终用 local.d 脚本
- 现象：NM 配置正确（keyfile + wifi.enabled + wpa_supplicant backend + <YOUR_WIFI_SSID>.nmconnection），
  但开机后 wlan0 仍 DOWN；`nmcli`/`iw` 未安装无法用 CLI 调试。
- 手动验证可行：`wpa_supplicant -B -i wlan0 -c wpa.conf -D nl80211` +
  `udhcpc -i wlan0 -n` → 秒连 <YOUR_WIFI_SSID> 拿到 IP。
- 尝试 OpenRC 服务 `wifiauto` 失败：LSB 头 `Required-Start` 在 OpenRC 不生效，
  `rc-status` 不识别该服务。`/etc/init.d/functions` 也不存在（Alpine 无此文件）。
- **最终方案**：写 `/etc/local.d/50-wifi.start`（`local` 服务已在 default runlevel，
  开机自动执行所有 local.d/*.start），内部等 wlan0 就绪 → 停 NM → 启 wpa_supplicant →
  udhcpc 取 IP。已验证：重启后可自动连上，SSH 恢复。

### SSH 免密登录（运维必备）
- 生成 ed25519 密钥对 `D:\pmos-images\sshkey\id_ed25519`（无口令）。
- 公钥写入设备 `/home/user/.ssh/authorized_keys`（600，user:user）。
- Windows 侧：`ssh -i <私钥> user@<DEVICE_IP>` 免密登录；`scp` 传文件。
