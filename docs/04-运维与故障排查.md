# 04 · 运维、故障排查与回滚

---

## 1. 功耗与散热（长期运行核心问题）

手机无主动散热，长时间高负载会触发降频。建议：

```bash
# 查看温度（热区）
for t in /sys/class/thermal/thermal_zone*/temp; do
  echo "$t: $(( $(cat $t) / 1000 ))°C"
done

# 查看 CPU 频率
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq

# 限制最大频率以控制发热（按需，数值以设备支持为准）
# echo 1113600 > /sys/devices/system/cpu/cpu0/cpufreq/scaling_max_freq
```

**实践建议**：
- 保持机身通风、避免阳光直射；可加散热片 / 小风扇。
- 负载控制在低功耗范围（轻量 Web、MQTT、代理），避免长时间 100% CPU。
- 若温度长期 > 70°C，考虑降频或迁移部分负载。

---

## 2. 电池长期插电

长期 100% 电量 + 高温会加速电池老化、鼓包。方案：

- **理想**：拆机断开电池，纯 USB 供电（需一定动手能力，注意保修/风险）。
- **软件**：若内核支持充电阈值，可限制上限（部分内核有 `charging_limit` 节点，需自行确认）。
- **监控**：定期观察电量与温度，避免高温满电长期存放。
- **安全**：使用可靠的 5V/2A 电源与数据线，避免劣质充电器。

## 3. 存储扩展（SD 卡）

Wiki 确认 SD 卡可用。`userdata` 仅 10GB，可挂载 SD 卡存放数据：

```bash
# 查看 SD 卡设备节点
lsblk

# 格式化（假设 /dev/mmcblk1，请按实际确认，⚠️ 会清空 SD 卡）
apk add e2fsprogs
mkfs.ext4 /dev/mmcblk1p1

# 挂载到 /mnt/sdcard
mkdir -p /mnt/sdcard
mount /dev/mmcblk1p1 /mnt/sdcard

# 开机自动挂载（/etc/fstab）
echo "/dev/mmcblk1p1  /mnt/sdcard  ext4  defaults  0  2" >> /etc/fstab

# Docker 数据目录迁移到 SD 卡（可选）
# 编辑 /etc/docker/daemon.json: {"data-root": "/mnt/sdcard/docker"}
```

> ⚠️ SD 卡 I/O 性能与寿命不如 eMMC，适合存放冷数据 / 日志，不建议放数据库热数据。

## 4. 日常运维

```bash
# 系统升级
apk update && apk upgrade

# 跨版本升级（edge 滚动）
pmbootstrap  # 设备上用 apk，主机侧用 pmbootstrap 重构建后重刷

# 查看服务状态
rc-status
rc-service <服务> restart

# 日志
dmesg | tail -50
logread | tail -50        # OpenRC 系统日志

# 备份（服务器跑起来后定期做）
tar czf /mnt/sdcard/backup-$(date +%F).tar.gz /etc /root /home
```

## 5. 回滚到 Android

若 postmarketOS 不稳定，可恢复原厂 LineageOS / 官方固件：

```bash
# 用阶段 A 备份的镜像恢复
cd D:\platform-tools
fastboot flash aboot     D:\backup\ugglite\<时间>\aboot.img
fastboot flash boot      D:\backup\ugglite\<时间>\boot.img
fastboot flash recovery  D:\backup\ugglite\<时间>\recovery.img
fastboot flash system    D:\backup\ugglite\<时间>\system.img
fastboot flash userdata  D:\backup\ugglite\<时间>\userdata.img
fastboot flash cache     D:\backup\ugglite\<时间>\cache.img
fastboot flash persist   D:\backup\ugglite\<时间>\persist.img
fastboot reboot
```

或从小米官方线刷包恢复（需 Mi Flash 工具 + 对应 ugglite 线刷包）。

## 6. 常见问题排查

### Q1：刷机后黑屏 / 无法启动
- **最可能原因**：未刷 lk2nd。补刷 `fastboot flash boot lk2nd-msm8952.img`。
- 若仍失败，重新 `pmbootstrap flasher flash_rootfs`，确认 rootfs 完整。

### Q2：无法 SSH 连接
- 确认 sshd 已启动：`rc-service sshd status`，未启动则 `rc-service sshd start`。
- USB 网络：主机侧 IP 是否设为 `172.16.42.2/24`；设备侧 `ip addr` 是否有 `172.16.42.1`。
- Wi-Fi：确认设备已连上同一网络，IP 是否正确。
- 防火墙：`rc-service iptables status`。

### Q3：Wi-Fi 搜不到 / 连不上
- 该端口 Wi-Fi 标记 works，但个别固件需额外步骤。查 Wiki 的 Wi-Fi 页面。
- 尝试 `nmcli device wifi rescan`；确认 `wpa_supplicant` 后台运行。
- USB 网络作为更可靠的备用通道。

### Q4：内存不足 / 服务被杀
- 2GB 内存偏紧：停掉不必要的服务，减少容器数量。
- 用 `htop` 定位占用进程；考虑 swap（`apk add swapfile` 或 zram）。

```bash
# 启用 zram（压缩内存，缓解小内存）
apk add zram-init
rc-update add zram-init default
rc-service zram-init start
```

### Q5：GPU / 图形异常
- 无头服务器无需图形，忽略即可。若需偶尔接屏，强制软件渲染（GTK4 已默认软件渲染）。

### Q6：相机 / OTG 不可用
- 已知限制（Broken），无解，非配置问题。

### Q7：pmbootstrap 构建失败
- 清理重试：`pmbootstrap zap -hc && pmbootstrap install`
- 查看日志：`pmbootstrap log`
- 确认使用 edge 通道（测试端口需要新内核）。

### Q8：WSL 中 fastboot 识别不到设备
- WSL2 USB 直通需额外配置（usbipd-win）。
- 更简单：在 Windows 侧用 `D:\platform-tools\fastboot.exe` 刷机，WSL 只负责 `pmbootstrap export` 导出镜像。

## 7. 安全建议（暴露到公网时）

- 优先使用 Tailscale / WireGuard 组网，避免直接端口映射。
- SSH 改密钥登录、禁用密码、改非 22 端口（可选）。
- 定期 `apk upgrade` 修补漏洞。
- 用 `ufw`/`iptables` 限制来源 IP。

```bash
apk add ufw
ufw allow from 192.168.1.0/24 to any port 22
ufw enable
```
