# 07 · 设备端配置参考

> 汇总设备上所有实际使用的配置，脱敏后集中于此。多数内容也可直接取用 `config/` 目录下的模板。
> 路径均为 postmarketOS（Alpine/OpenRC）设备上的绝对路径。

---

## 0. OpenRC / local.d 机制

`local` 服务已在 default runlevel，开机时按文件名顺序执行 `/etc/local.d/*.start`。本设备用编号控制顺序：

```
50-wifi  →  60-timesync  →  70-dashboard  →  80-pwrkey
（连网）     （NTP 对时）    （仪表盘）       （电源键亮灭屏）
```

`local` 服务需确保启用：

```bash
rc-update add local default
```

## 1. Wi-Fi 自动连接

### `/etc/wpa_supplicant/wpa-auto.conf`

见 `config/wpa-auto.conf.example`。核心：

```ini
ctrl_interface=/var/run/wpa_supplicant
update_config=1
country=CN

network={
    ssid="<YOUR_WIFI_SSID>"
    psk="<YOUR_WIFI_PASSWORD>"
    key_mgmt=WPA-PSK
}
```

权限必须为 600。

### `/etc/local.d/50-wifi.start`

见 `config/50-wifi.start`。逻辑：等 `wlan0` 就绪 → 停 NetworkManager（避免抢Interface）→ 起 `wpa_supplicant` → 等关联完成 → `udhcpc` 取 IP。日志写 `/var/log/wifiauto.log`。

> 为什么不用 NetworkManager 自动连？实测 NM 配置正确但开机 `wlan0` 仍 DOWN，且设备无 `nmcli`，排障困难；`local.d` 脚本方式稳定可靠。详见 `docs/06` 坑 19。

## 2. 时间同步

### `/etc/local.d/60-timesync.start`

```sh
#!/bin/sh
sleep 20
ntpd -q -n -p pool.ntp.org 2>/dev/null &
```

设备 RTC 无电池且不自同步，时间默认停在 1970；必须联网后 `ntpd -q` 对时。

## 3. USB 串口应急通道

### `/etc/inittab` 增加（保留 tty1 之外的串口登录）

```text
ttyGS0::respawn:/sbin/getty -L 115200 ttyGS0 vt100
```

仪表盘启用时会注释掉 tty1 的 getty（避免登录提示覆盖画面），但**保留 `ttyGS0`** 作为救急入口。

### USB ACM gadget（configfs）

设备用 configfs 把 USB 配成 CDC-ACM 串口，Windows 内置 `usbser.sys` 自动识别为 COM 口，无需签名 INF：

```sh
G=/sys/kernel/config/usb_gadget/g1
modprobe usb_f_acm
mkdir -p $G/functions/acm.0
mkdir -p $G/configs/c.1/strings/0x409
ln -s $G/functions/acm.0 $G/configs/c.1/acm.0
# 设置 idVendor/idProduct、strings 后绑定：
echo <UDC> > $G/UDC        # 本机为 ci_hdrc.0
```

> 为什么不走 NCM/RNDIS 网络？Windows 对自定义 VID/PID 报代码 28，第三方 INF 无签名被拒；详见 `docs/06` 坑 13/18。ACM 串口是唯一免驱稳定的通道。

## 4. 仪表盘自启

### `/etc/local.d/70-dashboard.start`

见 `config/70-dashboard.start`。要点：

- `echo 0 > /sys/class/vtconsole/vtcon1/bind` 解绑 fbcon，否则控制台重绘盖住画面
- 杀掉 tty1 getty 与旧 `pmos-dash`
- `nohup /usr/local/bin/pmos-dash &`

---

## 5. 电源键亮灭屏

### `/etc/local.d/80-pwrkey.start`

见 `config/80-pwrkey.start`。要点：

- 先按 PID 清旧实例（`pkill -x` 在 respawn 期间可能漏判）
- 置背光 255
- `nohup /usr/local/bin/pwrkey-blank &`

守护进程监听 `/dev/input/event0`（`pm8941_pwrkey`）的 `KEY_POWER`：短按（80 ms–2 s）翻转背光 `/sys/class/backlight/1a94000.dsi.0/brightness`，长按留给内核。状态写 `/run/pwr-screen-state`，仪表盘灭屏时跳过绘制省电。详见 `dashboard/README.md`。

## 6. SSH

- 配置项：`PermitRootLogin yes` / `PasswordAuthentication yes` / `PubkeyAuthentication yes`
- 密钥登录：`~/.ssh/authorized_keys`（600，属主正确）
- 修改后 `rc-service sshd restart`
- 备份：`/etc/ssh/sshd_config.bak-*`

## 7. 关键路径速查

| 用途 | 路径 |
|---|---|
| Wi-Fi 状态 | `wpa_cli -i wlan0 status` |
| 自动连网日志 | `/var/log/wifiauto.log` |
| 仪表盘日志 | `/var/log/pmos-dash.log` |
| 电源键日志 | `/var/log/pwrkey-blank.log` |
| 亮灭屏状态 | `/run/pwr-screen-state` |
| 背光 | `/sys/class/backlight/1a94000.dsi.0/brightness` |
| framebuffer | `/dev/fb0`（stride 2944 = `smem_len/yres`） |
| 电源键事件 | `/dev/input/event0` |
| 电量 | `/sys/class/power_supply/battery/capacity` |
| 温度 | `/sys/class/thermal/thermal_zone*/temp` |

## 8. 部署顺序（重刷镜像后）

1. 放入 `50-wifi.start`、`wpa-auto.conf`，`chmod +x` 并设配置 600
2. 配置 `ttyGS0` getty 与 ACM gadget
3. `rc-update add local default`，`rc-update add ntpd default`
4. 编译安装 `pmos-dash`、`pwrkey-blank`（见 `dashboard/README.md`）
5. 放入 `60-timesync.start`、`70-dashboard.start`、`80-pwrkey.start`，全部 `chmod +x`
6. `sudo reboot` 验收
